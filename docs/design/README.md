# Handoff: 太鼓判くん（Google口コミ支援サービス）

## Overview
飲食店などの店舗向け口コミ支援サービス。お客様はレジ横のQRコードを読み取り、★評価と「決め手」「おすすめメニュー」を選ぶだけで口コミ文の下書きができ、そのままGoogleの投稿画面へ進めます。店舗オーナーは管理画面で集計・届いたご意見・QR／卓上POPを管理し、運営は全店舗の発行と成績を管理します。

対象は5画面です。
1. ホームページ（サービス紹介）
2. 口コミページ（QRの読み取り先・お客様用）
3. 店舗オーナー用ログイン
4. 店舗管理（オーナー用）
5. 運営コンソール（運営用）

## About the Design Files
このフォルダのHTMLファイルは**HTMLで作ったデザインの見本**です。見た目と動きを示すプロトタイプなので、そのまま本番に使うコードではありません。見本をもとに、対象の環境で作り直してください。既存のコードベースがあればそのフレームワークとパターンに合わせ、なければ下の「推奨構成」を使ってください。

- 各 `.dc.html` は独自の小さなランタイム（`support.js`）で動きます。開くときは同じフォルダに `support.js` を置いてください
- ファイル内の `<script type="text/x-dc">` に、画面ロジック（状態・計算・文章テンプレート）がプレーンなJSで書かれています。挙動の正解はここを参照してください
- 数値・店舗・ご意見のデータはすべてサンプルです

## ⚠ 実装前に必ず対応：規約まわり
今のデザインには、Googleのクチコミポリシーと日本のステマ規制（景品表示法、2023年10月施行）に触れうる仕組みが2つあります。**実装時に必ず次のように変えてください。**

1. **レビューゲーティングの禁止**：今は★4未満のお客様にGoogle投稿ボタンを出さず、ご意見フォームへ回しています。Googleは高評価のお客様だけに口コミを依頼することを禁止しています。
   → **どの★でも「Googleに投稿」を選べる**ようにしてください。低評価のときはご意見フォームを「お店に直接伝える」選択肢として**追加**し、置き換えにはしないでください。
2. **見返りの禁止**：「投稿でもらえる特典」という表現は、投稿への見返りに当たります。
   → 特典は**回答してくれた全員**に出し、Googleに投稿したかどうかとは切り離してください。文言は「ご回答ありがとうございます。特典：〜」にします。
3. 自動生成した文章は**下書き**だと明記し、お客様が自由に直せる状態を保ってください（今のデザインでも編集できます）。

最終的な法的判断は専門家に確認してください。

## 推奨構成（新規で作る場合）
- **フロント**：Next.js（App Router）+ TypeScript。スタイルは Tailwind CSS か CSS Modules
- **DB・ログイン**：Supabase（Postgres・Auth・Row Level Security）
- **メール**：Resend（ご意見の通知、パスワード再設定）
- **公開先**：Vercel
- **QR生成**：`qrcode` パッケージ（PNG／SVG）。印刷用PDFは `@react-pdf/renderer` などで作る

### ルーティング
| パス | 画面 | 認証 |
|---|---|---|
| `/` | ホームページ | 不要 |
| `/r/[slug]` | 口コミページ（店舗ごと） | 不要 |
| `/login` | オーナー用ログイン | 不要 |
| `/owner` 以下 | 店舗管理（集計・ご意見・設定/QR） | owner |
| `/admin` 以下 | 運営コンソール（店舗一覧・新規発行・設定/QR・集計） | operator |

### データモデル（案）
```sql
stores (
  id uuid pk, slug text unique, name text,
  google_review_url text,
  aspects text[3],        -- 決め手の選択肢 例: {旨味,ビール,店員}
  menus text[3],          -- おすすめメニュー 例: {肉さし,ビビンバ,白米}
  coupon_text text null,  -- 特典メッセージ
  notify_email text,
  status text check (status in ('公開中','準備中','未発行')),
  plan text check (plan in ('スタンダード','ライト')),
  notify_on boolean default true, coupon_on boolean default true,
  updated_at timestamptz
)
profiles (id uuid pk = auth.users.id, role text check (role in ('operator','owner')), store_id uuid null)
events (                  -- 集計の元データ。1回の来店 = 1 session_id
  id bigserial pk, store_id uuid, session_id uuid,
  type text check (type in ('qr_open','star','aspect','menu','post_click','feedback_submit')),
  rating int null, value text null, created_at timestamptz default now()
)
responses (               -- 「届いたご意見」に出す1件
  id uuid pk, store_id uuid, session_id uuid, rating int,
  route text check (route in ('google','form')),
  tags text[], text text,   -- google: 生成した文章 / form: お客様の記入
  done boolean default false, created_at timestamptz
)
```
- RLS：owner は `store_id = profile.store_id` の行だけ読み書き可。operator は全件
- 口コミページからの書き込み（events／responses の insert）は匿名で許可し、slug→store_id は Edge Function かサーバー側で解決する。レート制限を入れる

### 2. 口コミページ — `Review Page.dc.html`
**目的**：お客様が★を選び、口コミ文を作ってGoogleに投稿する（スマホ専用、幅は最大430px）

- 背景 `radial-gradient(120% 60% at 50% 0%,#faf5ec 0%,#f3ece1 55%,#ece3d4 100%)`
- 上に「判 太鼓判くん」と「STEP n / 4」
- 白いカード（角丸26、影 `0 26px 50px -28px rgba(104,82,193,.55)`）。上部は紫グラデで「ご来店ありがとうございました」＋店名（27px 900）＋進捗バー（現在までは白の幅26px、残りは半透明白の幅18px、高さ4px）

**ステップ**
| step | 内容 |
|---|---|
| rate | 「今日のお食事はいかがでしたか？」。★5つ（各56px角、40px、未選択 `#ded5ef`／選択 `#6852c1`）。押すと押した星までが55msずつずれて跳ね（`starTap` .42s）、下に一言（★1「申し訳ありません…」〜★5「最高の評価、感激です！」）。480ms後に次へ |
| aspect | 「ありがとうございます！」＋「今日の決め手はどれですか？」。店舗設定の決め手3つをチップで。押して240ms後に次へ |
| menu | 「あと1つだけ／特に良かったメニューは？」。チップ3つ＋「選ばずに進む」 |
| positive | 「口コミ文ができました」＋「別の文にする」。文章を1文字ずつ表示（26msごとに2文字）。表示中は「生成中」バッジが点滅し、ボタンは薄紫の「文章を生成中…」で押せない。完成後は編集できる textarea（15px、行間1.85、背景 `#f8f6fd`、枠 `#ded5ef`）。「コピーしてGoogleに投稿」→ クリップボードにコピー → トースト表示 → 400ms後に Google の口コミURLを新しいタブで開く。押した後はボタンが緑 `#3f7a5c` で「コピー済み・Googleを開く」に変わる。特典があれば金色の点線カード |
| negative | 「お聞かせいただけますか」。気になった点のチップ（待ち時間／料理の味／接客／店内の清潔さ／価格、複数選べる）＋自由記述＋送信 |
| thanks | お礼の画面＋特典（「この画面を店員にお見せください」） |

- 「← ひとつ前にもどる」は aspect／menu／positive／negative で表示
- **文章の組み立て**：`書き出し + 決め手の文 + メニューの文 + 締め` をランダムに組み合わせる。テンプレート（`OPENERS`、`ASPECT_TEMPLATES`、`MENUS`、`CLOSERS`、`GENERIC`）は同じファイルのスクリプトにあります。決め手がテンプレートに無い語のときは `GENERIC` を使う
- **規約対応後の流れ**：positive は★に関係なく出す。★4未満のときは positive 画面の下に「お店に直接伝える」リンクを出し、negative へ進めるようにする
- **記録するイベント**：qr_open（ページ表示）、star、aspect、menu、post_click、feedback_submit

### 5. 運営コンソール — `Operator Console.dc.html`
共通の枠は店舗管理と同じ（ヘッダーは「運営コンソール」）。**メニュー**：店舗一覧／新規ページ発行／店舗設定・QR／集計

- **店舗設定・QR**：店舗管理と同じ
- **集計**：
  - 数値カード：稼働店舗（公開中 / 全体、補足「準備中 n 店舗」）、今月のタップ数と前月比、投稿到達率、要フォロー

  - 時間帯別のタップ数、プラン別（平均タップ・到達率）、週ごとのタップ数、★の分布、投稿までの到達
  - 数字は同じ元データから計算して、画面の中で食い違わないようにする（★分布の合計 = ファネルの「★をタップした」）
